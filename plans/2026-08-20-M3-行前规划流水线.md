# M3 实施计划：行前规划流水线

> **For agentic workers:** 按任务顺序执行。已授权在本项目目录内 git add/commit。壳文件 `行程助手.html` 是 CRLF，用内容匹配 Edit。`test/smoke.test.js` 只追加不动旧段。**任何任务都不得真实调用 DeepSeek API**——测试全部走 mock fetch。

**Goal:** 让程序自己当规划师：行程库首页新增"新建行程"→ 对话向导收需求 → AI 生成骨架、用户自然语言对稿 → 分批烘焙全部内容（带进度、断点续跑）→ 自动验证（存在性/史实交叉检查，三档报告）→ 组装成 TripPack 入库。

**Architecture:** 全部长驻 `行程助手.html`。规划器状态 `PLANNER` 持久化在 localStorage `ta-planner`（全局一份草稿），每个批次完成即落盘 → 断点续跑。LLM 调用统一走 `dsJSON(userPrompt,opts)`（JSON mode、低温、deepseek-v4-flash 失败回退 deepseek-chat、最多 2 次重试、返回已 parse 的对象）。DeepSeek key 复用现有 `'ta-ds-key'`（aiScan 同款）。

**前置事实：**
- 壳内已有：aiScan/aiPoiDetail 的 DeepSeek 调用范式（fetch `https://api.deepseek.com/chat/completions`、model 先试 `deepseek-v4-flash` 400 回退 `deepseek-chat`、`response_format:{type:'json_object'}`）；`showPicker(trips)` 行程库首页（M2）；`validatePack` 壳内轻校验；完整校验器 `tools/validate-trip.js`（Node）。
- `test/boot.js`：`boot(htmlPath,seed)` → `{ctx,document,localStorage}`。
- TripPack schema：见 `tools/validate-trip.js` 顶部注释与 `trips/sanxia.trip.json` 实例。

**PLANNER 状态形状（全流程契约，三个任务共用）：**

```js
PLANNER = {
  step: 0,              // 0 向导 1 骨架对稿 2 烘焙 3 验证 4 完成
  req: null,            // {title,from,to[],days,startDate,kidAge,theme,modes,rhythm,mustAvoid,needFlex,flexDays,flexCount}
  skeleton: null,       // S1 产物，见下
  baked: {              // S2 逐批填充（每批落盘）
    pois:null, poiDetail:null, radarExtra:null, bookings:null,
    flex:null, wxCities:null, wxRules:null, legInfo:null
  },
  verify: null,         // S3 产物 {pass:[],corrected:[],pending:[],poiFixes:{}}
  log: []               // 进度日志字符串数组
}
```

**S1 骨架 JSON 形状（dsJSON 返回值契约）：**

```js
{meta:{title,kicker,routeLine,kidAge,theme,region:'cn',dateStart,dateEnd,preDepartNote,endNote},
 anchors:{key:{name,lat,lng,stay}},              // key 为 2 字母拼音缩写
 days:[{n,date,full,wd,title,meta,type,anchor,plan[],know[],tags[]}],  // plan/know 为完整内容，S2 不再补
 legs:[{id,keys,label,mode}],
 culture:{groups:[[seg,label]],hint},
 flex:null|{daysCount,options:[{key,name,short,anchor,note,rows:[],know:[]}]},  // S1 只出草案,rows/know 由 S2 填
 wxCityNames:['城市名',...]}                       // S2 用来生成 wxCities
```

**dsJSON 契约：**
```js
function dsJSON(userPrompt,opts){ // opts:{sys,maxTokens,temp}
  // POST api.deepseek.com/chat/completions,model 先试 deepseek-v4-flash,HTTP 400 回退 deepseek-chat
  // body:{model,temperature:opts.temp||0.3,response_format:{type:'json_object'},max_tokens:opts.maxTokens||4000,
  //       messages:[{role:'system',content:opts.sys||'你是亲子旅行规划师,只输出 JSON。'},{role:'user',content:userPrompt}]}
  // 成功:JSON.parse(choices[0].message.content) 返回;解析失败或 HTTP 失败重试,最多共 3 次尝试,全失败 throw
}
```

- [ ] **Step 2: 实施**

1. `startVerify()`（替换占位）：step=3；两路并行（Promise.allSettled）：
   - **坐标路**：逐 POI（pois+radarExtra）调 Nominatim `https://nominatim.openstreetmap.org/search?format=json&limit=1&countrycodes=cn&q=<name>`，请求间隔 1.1s（免费服务礼仪）。命中且距原坐标 ≤0.15° → pass；命中但偏远 → 用 Nominatim 坐标替换并记 corrected（`verify.poiFixes[name]={lat,lng}`）；未命中 → 进 LLM 路复核。
   - **LLM 路**：全量点名+坐标+info 一批 dsJSON 交叉复核（"是否真实存在、坐标是否大致正确、简介有无史实错误"）→ `{results:[{name,ok,reason?}]}`。Nominatim 未命中的点以 LLM 路为准：ok→pass(!corrected)，不 ok→pending。
2. 报告页 UI：三档分组列表（✅通过 N / 🔧已纠偏 N 列坐标变化 / ⚠️待确认 N 每条带"保留/丢弃"按钮→`resolvePending(name,keep)`）。全部 pending 处理完才亮 `完成,加入行程库` 按钮。
3. `assemblePack()`：skeleton + baked + verify.poiFixes 应用 + pending 丢弃名单 → 组装完整 TripPack：meta（补 id：`req` 标题拼音/时间戳即可，如 `'t'+Date.now()`）、anchors/days/legs/culture/flex（baked.flex 的 options 组装成 schema 形状：insertBeforeDay/doneKey/dateStart/dateEnd 由 skeleton.flex 草案与 days 推算——insertBeforeDay = 机动段后一天的 n，doneKey = 机动首天 n，badge 由天数生成 `D10–13` 式）、pois/radarExtra/poiDetail/bookings/wxCities/wxRules/legInfo、optimize（order=mainPath 推算：days 里 anchor 首现顺序+home 在前、anchorDays 由 days 归纳、home=出发地 anchor、note 通用文案）、map（center=anchors 经纬度均值、zoom 5、mainPath、fitAnchors=全部 anchor key）、ai（`{radiusKm:100,routeKm:20,cats:['文','史','地','科']}`）。组装后跑壳内 `validatePack` + 深度自检（poiDetail 覆盖），不过则报错误页显示具体问题。
4. `finishPlanner()`：写 `ta-trips[id]=pack`、`ta-current=id`、清 `ta-planner`、location.reload() 进新行程。
